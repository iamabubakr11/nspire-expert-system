# Кейс-задача № 3
## Разработка прототипа экспертной системы для Nspire Dev

### 1. Выбор предметной области

В качестве предметной области выбрана поддержка принятия решений при подборе типа веб-проекта для клиентов Nspire Dev. Цель прототипа — автоматизировать первичную консультацию: по ответам клиента рекомендовать лендинг, корпоративный сайт, сайт-каталог, интернет-магазин или веб-приложение и объяснить причину выбора. Предлагаемый инструмент соответствует направлению деятельности Nspire Dev в области веб-разработки.

### 2. Анализ существующих решений

При выборе инструментов были рассмотрены специализированные оболочки экспертных систем: **CLIPS**, **Jess**, **EMYCIN**, **FirstClass** и **GURU**. CLIPS — продукционная экспертная оболочка, поддерживающая факты, правила вида «ЕСЛИ — ТО» и механизм логического вывода; её удобно интегрировать с Python через CLIPSPy. Jess также работает с правилами и хорошо подходит для проектов на Java, но потребовал бы другого технологического стека. EMYCIN исторически использовалась для создания консультационных систем с неопределённостью, однако для компактного веб-прототипа неудобна. FirstClass и GURU относятся к более ранним подходам/продуктам экспертных систем, материалы и возможности современных интеграций для них ограничены. Для учебной задачи выбрана **CLIPS** ввиду понятного синтаксиса, наличия правил и удобной интеграции с Flask.

### 3. Разработка базы знаний

База знаний создана в файле `expert/rules.clp`. Входные факты описывают цель сайта (`products`, `company`, `campaign`), необходимость онлайн-оплаты (`yes/no`) и личных кабинетов (`yes/no`). Система содержит пять продукционных правил. Например: «ЕСЛИ цель — продажа товаров, нужна онлайн-оплата и не нужны личные кабинеты, ТО рекомендовать интернет-магазин». При потребности в личных кабинетах приоритет имеет веб-приложение. Правила имеют приоритеты, что предотвращает неоднозначные решения.

### 4. Механизм логического вывода

Для логического вывода используется **CLIPS** с библиотекой **CLIPSPy**. Flask передаёт ответы пользователя в Python-модуль `expert/engine.py`, который создаёт отдельную рабочую среду CLIPS, загружает базу знаний, добавляет входные факты и запускает правила. Результат формируется в виде рекомендации и идентификатора сработавшего правила. Решение принимает механизм CLIPS, а не логика интерфейса.

### 5. Интерфейс пользователя

Веб-интерфейс реализован с помощью HTML, CSS и JavaScript. Пользователь отвечает на три вопроса, нажимает кнопку анализа и получает тип сайта, описание, ключевые функции и объяснение с указанием правила. Интерфейс адаптирован для компьютеров и смартфонов. Обмен данными с сервером осуществляется через HTTP API Flask.

### 6. Тестирование и отладка

Для проверки предусмотрены функциональные сценарии: продажа с оплатой — интернет-магазин; продажа без оплаты — сайт-каталог; представление организации — корпоративный сайт; продвижение одной услуги — лендинг; наличие личных кабинетов — веб-приложение. Автоматические тесты в `tests/test_expert.py` дополнительно охватывают все 12 комбинаций входных данных, некорректные ответы и API. **Фактические результаты и скриншоты следует внести после запуска проекта и выполнения тестов на компьютере.**

### 7. Заключение и рекомендации

Подготовлен прототип экспертной системы, ориентированный на поддержку первичного выбора веб-продукта для клиентов Nspire Dev. Его преимущества — прозрачные правила принятия решений, объяснимость рекомендаций и простота расширения базы знаний. В дальнейшем целесообразно добавить оценку бюджета, сроков и сложности проекта, расширить правила, предусмотреть сохранение истории консультаций и провести тестирование с реальными специалистами компании. Прототип не заменяет полноценный сбор технических требований.
